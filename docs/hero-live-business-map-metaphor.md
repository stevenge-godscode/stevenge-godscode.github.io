# Genesis 首图隐喻：实时业务地图

> 目标：用一个业务用户无需技术背景也能理解的视觉比喻解释 Genesis，同时保证技术负责人继续看时不觉得概念失真。

## 1. 核心隐喻

> **通用 AI 面对企业业务世界几乎是一眼黑。Genesis 就像给 AI 一张实时业务地图，让它知道现在发生了什么、这些事情意味着什么、接下来可以怎么做。**

这里不使用“静态地图”，而使用 **Live Business Map / 实时业务地图**。

原因：企业业务不是静态知识。客户、合同、项目、订单、设备、行情、风险状态持续变化。Genesis 不只是告诉 AI “世界长什么样”，还要告诉它“现在发生了什么”。

---

## 2. 地图元素与 Genesis 概念的对应关系

| 地图隐喻 | Genesis 概念 | 解释 |
|---|---|---|
| 地标 / 道路 | Business Object / Relationship | 客户、合同、项目、订单、服务、设备等对象以及彼此关系 |
| 实时路况 | Facts / Events / Evidence | 当前订单、逾期、告警、验收、市场状态等实时事实 |
| 地图图层 | Context | 当前任务只打开与问题相关的业务图层 |
| 交通规则 | Rules / Methods / Boundaries | 企业怎么判断、什么允许、什么禁止、什么需要审批 |
| 导航路径 | Business Capability | 针对一类业务任务可重复使用的判断与工作路径 |
| 路线执行 | Agent / Workflow / API / Human | 真正创建任务、发起流程、更新系统、人工确认 |
| 新路况 | New Facts | Action 改变业务状态后形成新的事实并重新进入地图 |

最重要的表达：

> **地图不是数据仓库。它是 Genesis 基于现有数据、业务语义、实时事实、规则和能力形成的 AI 可用业务世界。**

---

## 3. 首图只表达三态

不要继续使用四个或五个架构模块并排。

### A. 没有 Genesis

画面：一个有真实业务结构但被暗雾遮住的“企业业务世界”。

AI 在地图之外，只能看到一些散落的数据点 / 文档标记，不能理解彼此关系。

只显示一句：

> **看不见企业业务世界**

可极小显示三个结果：

> 不知道发生了什么 · 不知道意味着什么 · 不知道怎么做

### B. Genesis

Genesis Logo 位于地图图层控制中心。

核心文字：

> **实时业务地图**

地图由四个非常克制的图层组成：

- 对象与关系
- 当前事实
- 规则与边界
- 可执行路径

### C. 有了地图之后

同一个业务世界被点亮。

地图里只显示一个具体业务 instance，例如：

- 战略客户A
- 合同A
- 项目A
- 应收A `逾期18天`

高亮一条行动路径：

> **重点关注 → 请求验收状态 → 发起风险复核**

AI 不再只是输出一段文字，而是知道：

> **现在发生了什么 → 当前意味着什么 → 下一步可以做什么**

## 4. 视觉构图

建议整个 Hero 使用 **一张连续地图画布**，而不是四张卡片。

```text
┌───────────────────────────────────────────────────────────────┐
│                                                               │
│   通用 AI           Genesis 实时业务地图          AI + MAP    │
│                                                               │
│   [AI]              ┌─────────────────┐                       │
│      ↘               │ 客户A ─ 合同A   │       看见当前状态     │
│     █████            │   │      │      │       理解业务关系     │
│   █ 雾区 █     →      │ 项目A ─ 应收A   │  →    找到行动路径     │
│     █████            │        逾期18天 │                       │
│                      │   ──▶ 风险复核  │                       │
│                      └─────────────────┘                       │
│                                                               │
│                    Action → 新事实 ↺                           │
└───────────────────────────────────────────────────────────────┘
```

实际页面不需要放这么多字。重点是视觉上让用户一眼看到“从黑到清晰”。

---

## 5. 动效

只保留一个 Hero 动效：**地图逐渐点亮 / 雾层退去**。

推荐 10–12 秒循环：

1. 开始时左侧业务地图大部分处于雾化 / 低对比；
2. Genesis Logo / map layer 被激活；
3. 关系线、对象节点和当前 Fact 逐步显现；
4. 最后高亮一条 Action Route；
5. Action 后出现一个新的 Fact marker；
6. 轻微复位循环。

不要使用：

- 多个小点一直闪烁；
- 数据流飞线；
- 机器人动画；
- 复杂地图缩放；
- 彩色交通地图效果。

保持白 / 灰 / 黑 / Genesis 蓝。

## 6. Hero 文案建议

主标题继续固定：

> **让 AI 真正为你的公司工作**

副标题建议压缩为：

> **Genesis 给通用 AI 一张实时业务地图 让它看见企业事实 理解业务关系 并找到正确的行动路径**

如果需要更产品化：

> **Genesis 把企业事实 业务关系 规则和行动路径组织成 AI 可持续使用的实时业务地图**

首图内部只出现三个主标签：

> **看不见业务世界**

> **Genesis 实时业务地图**

> **看见状态 找到行动路径**

---

## 7. 技术边界

地图隐喻不能导致以下误解：

- Genesis 不等于把全公司数据复制成一张知识图谱；
- 地图不是一个静态 Ontology；
- 当前 Facts 可以来自实时联邦查询、事件、缓存或物化；
- Action 仍可由现有 Agent、Workflow、API 和人工执行；
- Genesis 的核心是让 AI 使用统一的 Business Context & Capability，而不是替换现有 Data / AI / Agent 平台。

因此技术下钻仍然保持：

> **Business Model + Facts + Context + Rules / Boundaries + Capability**

但这些不需要出现在首图正文里。
