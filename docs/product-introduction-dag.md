# Genesis 产品介绍 DAG

> 目标：把 Genesis 的官网产品介绍从“功能说明”整理为一个完整的客户认知闭环。后续按 DAG 节点逐个讨论、定稿，并在完成后同步到首页。

## 工作原则

- 首页优先服务：**已经想用 AI、甚至已经试过通用 AI，但发现进入真实企业业务后不好用**的业务负责人和技术负责人。
- 页面主线始终是：**痛点 → 为什么会这样 → Genesis 补了什么 → 达成什么价值**。
- 不把 Genesis 讲成“另一个大模型 / RAG / Agent / 数据平台”。
- 不贬低现有技术。重点解释各层分别解决什么问题，以及 Genesis 补的是哪一层。
- 首页先讲客户问题和商业价值，技术术语用于后续解释“为什么可信、为什么不同、怎么落地”。
- 一次只定稿一个主节点；节点必须有：结论、用户疑问、回答方式、页面表达、验收标准。

# N00 DONE：目标用户

## 第一目标用户

业务负责人 / 管理者：

- 已经使用豆包、DeepSeek、ChatGPT、Kimi 等通用 AI。
- 认可模型能力，但发现真正问公司业务时，需要不断解释背景，回答也不敢直接用于判断和执行。
- 诉求不是“再买一个 AI”，而是：**有没有 AI 真正懂我的业务，并能长期参与工作？**

## 第二目标用户

技术团队 / AI 团队负责人：

- 已经有数据平台，或正在建设知识库、RAG、Agent、Workflow 等能力。
- 发现每个 AI 应用都在重复处理业务语义、字段含义、规则、上下文、权限和事实。
- 诉求是：**能否建立统一、持续、可复用的企业业务理解层，让不同模型、Agent 和应用共同使用？**

共同触发场景：

> **我们想用 AI，也已经试过，但它一进入真正的企业业务就不好用了。**

# N01 DONE：通用 AI 为什么一进企业业务就不好用

## 用户感受到的症状

1. **每次都要重新解释**：公司背景、术语、客户、项目、当前任务需要反复告诉 AI。
2. **给了资料也未必真正看懂**：拿到文档、数据库字段，不等于知道其业务含义。
3. **回答像那么回事，但不敢真用**：AI 不知道企业自己的判断标准、工作方式和边界。

## 根因

不是模型不够聪明，而是通用 AI 天生缺少企业私有的三层信息：

### 1. 企业事实

> **现在真正发生了什么？**

数据、状态、时间、来源、当前可信事实。

### 2. 业务语义与上下文

> **这些信息在这家公司意味着什么？**

业务对象、关系、字段含义、状态含义、历史和任务上下文。

### 3. 企业工作方式

> **这家公司遇到这种情况应该怎么判断和工作？**

规则、指标、方法、流程、权限和边界。

因此可以压缩为：

> **事实 → 理解 → 行动**

即：

> **不知道发生了什么 → 不知道这意味着什么 → 不知道该怎么做。**

## 核心表达

> **通用 AI 很聪明，但一到你的公司就不好用了。**

解释：

> **不是模型不够强，而是它没有你公司的企业事实、业务上下文和工作方式。**

N01 完成标准：目标客户能在 5–10 秒内认出自己的使用挫败感，并理解问题不在“模型智力”。

# N02 CURRENT：AI + 数据之间的业务理解断层

## 核心判断

企业现在通常已经有两端：

- **Data**：ERP、CRM、数据库、数据仓库、Lakehouse、文档、日志、指标体系。
- **AI**：DeepSeek、Qwen、GPT、Claude、RAG、Agent、Workflow。

常见假设是：

> **有 AI + 有企业数据 = 企业 AI。**

但这里少了一步：

> **数据本身不会自动变成业务理解。**

AI 可以拿到 `customer_id=10382`、`status=2`、`amount=8000000`，但并不会天然知道：

- 10382 是否是战略客户；
- status=2 在这家公司代表什么业务状态；
- 800 万在当前客户、合同和项目背景下意味着什么；
- 公司遇到这种情况通常如何判断；
- 哪条规则应该生效；
- 当前证据是否足够；
- AI 是否有权继续执行。

这就是 **AI 与企业数据之间的“业务理解断层”**。

## 建议的架构模型

```text
业务系统 / 企业数据
        ↓
    Data Platform
        ↓
 Business Semantic & Context
        ↓
      AI / LLM
        ↓
   Agent / Application
```

其中 Genesis 要解决的是中间这层，而不是替换上下任何一层。

## 各层回答的问题

| 层 | 首要问题 |
|---|---|
| Data Platform | 数据在哪里？值是什么？如何治理、计算和提供？ |
| Genesis Business Semantic & Context | 这些数据在业务上意味着什么？当前事实是什么？应该按什么规则理解和使用？ |
| AI / LLM | 基于这些上下文如何推理、生成和判断？ |
| Agent / App | 最终完成什么业务任务？ |

一句人话：

> **数据平台把数据准备好；Genesis 把业务讲明白；大模型负责思考；Agent 负责干活。**

## 与传统数据平台比较时必须避免的错误

不能说“数据平台没有语义”。成熟数据平台可能已经具备：

- 元数据 / 数据目录；
- 主数据；
- 指标体系；
- BI Semantic Layer；
- Knowledge Graph；
- 数据治理。

Genesis 的差异不是“我们有语义，你没有”，而是**语义最终服务的对象和深度不同**：

> 传统数据语义主要帮助人、BI 和数据应用正确理解和使用数据；Genesis 要进一步把业务对象、关系、事实、规则、上下文、方法、证据和边界组织成 **AI 可持续使用的业务上下文**，用于判断和工作。

因此更准确的表达是：

> **Genesis 不是传统 Semantic Layer 的替代，而是面向 AI 工作的企业业务语义与上下文层。**

## N02 候选核心表达

优先级 A：

> **企业不缺 AI，也不缺数据。真正缺的是 AI 与数据之间的业务理解层。**

优先级 B：

> **AI 缺的不是更多数据，而是知道这些数据在你的公司意味着什么。**

优先级 C：

> **数据平台让数据可用；Genesis 让 AI 理解数据背后的业务世界。**

## N02 验收标准

- 业务用户能理解为什么“把数据给 AI”仍然不等于“AI 懂业务”。
- 技术负责人不会觉得我们在错误贬低数据平台或传统 Semantic Layer。
- 能清楚指出 Genesis 的必要位置：**Data 与 AI 之间的企业业务语义与上下文层**。
- 自然引出下一问：**“那 Genesis 到底是什么？”**

# N03 DRAFT：Genesis 到底是什么

当前建议技术定义：

> **Genesis 是连接企业数据与通用 AI 的业务语义与上下文平台。**

完整解释：

> **Genesis 将企业的业务对象、关系、事实、规则、上下文、方法、证据和权限组织成统一、持续、可复用的 AI 业务上下文，让通用 AI 获得企业业务认知。**

业务语言：

> **Genesis 把你的公司教给 AI。**

产品逻辑必须区分三件事：

1. Genesis **组织和提供**：Semantic / Facts / Context / Rules / Methods / Evidence / Boundaries。
2. AI 基于这些信息形成：**企业业务认知**。
3. Agent / App 基于认知完成：**判断与行动**。

因此不要简单说“Genesis 存储认知”。更准确是：

> **Semantic + Facts + Context + Rules → AI Cognition → Action**

N03 仍需继续讨论并定稿产品类别名称、中文正式定义、英文正式定义，以及“一句不是什么”。

# 后续节点方向

## N04 核心机制

要回答：Genesis 如何把 Data 变成 AI 可用的 Business Context；Ontology、Fact、Evidence、Rules、Capability 各自承担什么作用。

## N05 Domain Pack

当前方向：

> **Domain Pack = Domain Semantics × Company Context**

中文：

> **专业领域模型 × 企业自己的业务方式。**

## N06 边界与比较

在 N02 的架构定位稳定后，再详细处理：

- Data Platform / Semantic Layer；
- Knowledge Base / RAG；
- Knowledge Graph；
- Fine-tuning；
- Agent / Workflow。

目标不是证明谁“更高级”，而是说明它们与 Genesis 各自负责哪一层、如何协作。

## N07 可信可控

核心原则候选：

> **有依据才判断；没有依据，就明确说不知道。**

需要进一步说明 Evidence、权限、边界、人审、可追溯。

## N08 系统共存

核心方向：现有 ERP、CRM、数据库、数据平台、知识库、LLM、Agent、App 全部可以继续使用；Genesis 增加中间的企业业务语义与上下文层。

## N09 最终价值

不能只停留在“懂专业 / 懂公司”，需要上升到：

- 判断更可靠；
- 更少重复解释和重复建设；
- AI 能真正进入业务；
- 企业规则和专家经验可沉淀、复用；
- 不同模型和 Agent 共享统一的企业业务认知基础。
