# N09：Genesis 最终客户价值框架

> 核心问题：客户为什么愿意为 Genesis 付费？“AI 更懂业务”只是能力，不是最终价值。

## 1. 核心判断：价值不是让 AI 回答更多，而是让更多真实工作可以交给 AI

Genesis 的价值主线不应停在：

> AI 更懂业务 / 回答更准确。

更完整的变化是：

```text
能回答
   ↓
能基于企业事实和方法判断
   ↓
能在边界内完成真实任务
   ↓
同一业务能力可被多个 AI / Agent / App 复用
   ↓
企业的专业工作方式持续沉淀成数字能力资产
```

因此最强的价值表达候选：

> **不是让 AI 回答更多，而是让更多工作真正可以交给 AI。**

---

# 2. 五级价值阶梯

## L1 — Useful：从“通用回答”到“业务可用”

Genesis 让 AI 拥有企业事实、业务语义和上下文。

用户获得：

- 不必每次重复解释公司背景；
- 回答针对当前业务对象和当前状态；
- 少一些“听起来对、业务上不能用”的内容。

价值不是“回答更漂亮”，而是：

> **第一次开始回答企业真正的问题。**

---

## L2 — Reliable：从“像答案”到“可以作为判断依据”

通过 Facts、Rules、Methods、Evidence、Boundary：

- 关键结论可以回到来源；
- 规则和模型推理边界清楚；
- 证据不足时可以 abstain / escalate；
- 判断过程可以审计。

价值：

> **AI 从信息助手开始进入业务判断。**

这里不承诺 AI 永远正确，而是提高“可采用性”和“可治理性”。

---

## L3 — Actionable：从“给建议”到“完成工作”

Business Capability 把：

- Context；
- Rules / Methods；
- Evidence；
- Permission；
- Allowed Actions；

组合成稳定业务能力。

例如：

- 客户风险判断并创建跟进任务；
- 故障评估并自动扩容；
- 学习诊断并生成待确认学习计划；
- 经营异常识别并发起复核流程。

价值：

> **AI 不再只告诉人“应该怎么做”，而是能在企业边界内把一部分工作真正做完。**

---

## L4 — Reusable：从“一个 AI 项目”到“企业共享能力”

传统方式下：

```text
App A → 自己做 Prompt / RAG / Rules / Context
App B → 再做一遍
Agent C → 再做一遍
```

Genesis：

```text
CustomerRiskAssessment
        ↓
App A / Agent B / Copilot C / Workflow D
```

价值：

- 业务定义不再每个项目复制；
- Rules / Methods 更新一次，多场景生效；
- 新 Agent / App 不必从头学习公司；
- 更容易切换 / 组合不同模型。

对技术负责人，这是 Genesis 最直接的平台 ROI：

> **一次沉淀，多处复用。**

---

## L5 — Compounding：从“使用 AI 工具”到“沉淀企业 AI 业务能力资产”

企业真正稀缺的不只是数据，而是：

- 业务对象怎么定义；
- 专家怎么判断；
- 哪些 Evidence 才够；
- 哪些条件算异常；
- 什么可以自动做；
- 什么必须人工确认。

过去这些内容散落在：

- 人脑；
- SOP；
- Excel；
- Prompt；
- 代码；
- Workflow；
- 单点 Agent。

Genesis 把它们逐步沉淀为：

> **Business Model + Rules / Methods + Context Logic + Business Capability**

最终企业拥有的不只是若干 AI 应用，而是一套可持续复用和演进的 **AI Business Capabilities**。

这是长期战略价值。

# 3. 不同角色真正购买的价值不同

## 业务负责人

最关心：

- AI 是否真正理解当前业务；
- 结果能不能用；
- 能不能减少人工重复分析；
- 能不能把部分工作稳定交给 AI；
- 关键结果是否有依据和边界。

推荐价值语言：

> **更懂当前业务。**

> **判断更有依据。**

> **更多工作真正做完。**

不要先说 Ontology、Context Platform、Capability Contract。

---

## 技术 / AI 团队负责人

最关心：

- 每个 Agent 是否还要重建业务逻辑；
- Data / KG / RAG / Model / Agent 是否能继续复用；
- 业务定义能否统一治理；
- 新场景上线是否越来越快；
- 模型是否可替换；
- 权限、Evidence、Audit 能否统一。

推荐价值语言：

> **业务理解一次沉淀，多模型、多 Agent、多 App 复用。**

> **减少每个 AI 应用重复建设的 Business Glue。**

---

## CIO / CTO / 管理层

最关心：

- 已有 IT / Data / AI 投资能否保护；
- AI 建设是不是继续碎片化；
- 企业专业能力能否成为长期资产；
- 风险是否可治理；
- 平台投入是否会随着场景增加产生复用收益。

推荐价值语言：

> **不替换现有技术栈，把分散的 AI 项目逐步沉淀成企业共享的业务能力。**

---

# 4. Genesis 的价值不应该只讲“效率”

企业 AI 常见产品介绍容易只讲：

> 降本、提效、提高准确率。

这些都成立，但太泛，而且没有项目数据时不应给具体 ROI 数字。

Genesis 更具有辨识度的价值可以分成四类：

| 价值 | 客户看到的变化 |
|---|---|
| **业务可用性** | AI 从泛泛回答变成理解当前公司事实和业务含义 |
| **业务可交付性** | 从建议进入受控判断、流程和 Action |
| **平台复用性** | Business Context / Capability 跨模型、Agent、App 使用 |
| **组织沉淀性** | 专家方法、业务规则和工作方式从个人 / 项目资产变成企业资产 |

Trust / Governance 是让上述价值能够进入生产环境的前提，而不仅是第五个独立卖点。

---

# 5. 最值得首页表达的价值，不超过三项

首页如果展示五级价值会太重。

建议压缩成三件事：

## 1. 判断更可靠

> **基于企业当前事实、规则和 Evidence，而不是只靠模型猜。**

## 2. 真正能做事

> **从回答问题进入判断、协作和受控执行。**

## 3. 能力持续复用

> **形成的业务理解和能力，可以继续给更多模型、Agent 和应用使用。**

这三个价值正好对应：

```text
当前业务结果
    +
真实工作完成
    +
长期平台复利
```

# 6. 一个更强的价值主张结构

Hero 主价值仍建议：

> **让 AI 真正为你的公司工作。**

其下不要马上讲功能，而可以用一条递进：

> **懂你的业务 → 按你的方式判断 → 在边界内把工作做完 → 能力继续复用。**

更商业化的压缩：

> **从“会回答”到“能工作”。**

但单独使用这句话太容易被 Agent 产品复制，因此必须与 Genesis 独特原因绑定：

> **让 AI 基于你的业务事实、规则和方法，从“会回答”走向“真正能工作”。**

# 7. 价值必须在 N10 用指标验证，而不能现在编数字

N09 只定义“应该测什么”，不承诺未经验证的百分比。

## 业务结果指标候选

- Decision Lead Time：从问题出现到形成可采用判断的时间；
- Task Completion Time：一个业务任务端到端耗时；
- Human Touches：需要人工介入次数；
- Rework Rate：AI 输出被返工 / 推翻比例；
- Resolution Rate：AI 能完成或推进到明确下一步的任务比例；
- Evidence Coverage：关键判断中可追溯 Evidence 覆盖程度；
- Escalation Quality：应该 abstain / 人审的情况是否正确升级。

## 平台复用指标候选

- Capability Reuse Count / Ratio；
- Shared Rules / Context Reuse；
- New Scenario Time-to-Value；
- 新 Agent / App 需要新增多少 Business Glue；
- 模型切换时业务逻辑改造量；
- 重复 Prompt / Rule / Mapping 数量减少程度。

## 组织沉淀指标候选

- 已数字化 Business Capability 数量；
- Capability 覆盖的业务任务；
- 专家规则 / 方法版本化程度；
- Capability 跨团队 / App 使用次数；
- Business Decision Trace 可审计覆盖率。

这些指标在有 POC / 客户数据后再填真实数字。

# 8. 场景实例：客户风险判断的价值如何发生

## 原来

业务经理：

1. 从 CRM 查客户；
2. 从 ERP 查应收；
3. 找项目负责人问验收；
4. 找合同条款；
5. 根据个人经验判断风险；
6. 创建跟进任务。

## 只有通用 AI / RAG

可以总结合同和数据，但仍需要人告诉它：

- 哪些数据重要；
- 什么算风险；
- 这个客户为什么特殊；
- 什么情况下不能直接下结论。

## Genesis

`CustomerRiskAssessment` 自动形成：

- 相关客户 / 合同 / 项目 Context；
- 当前 Facts；
- 企业 Risk Rules；
- Evidence；
- Allowed Actions。

结果：

> AI 可以形成有依据的风险判断，并在权限范围内创建后续任务；证据不足时明确升级给人。

这个场景对应三类价值：

- **业务**：减少信息查找和重复判断；
- **质量**：同一套规则、Evidence 和边界；
- **平台**：同一个 `CustomerRiskAssessment` 可以被经营看板、Copilot、Agent、移动 App 共同使用。

---

# 9. N09 验收标准

- 不把“AI 更懂业务”当成最终价值；
- 能形成从 Useful → Reliable → Actionable → Reusable → Compounding 的价值阶梯；
- 业务负责人和技术负责人的付费理由分别清楚；
- 首页最终只保留 2–3 个强价值，而不是价值墙；
- 不使用未经 POC / 客户数据验证的 ROI 数字；
- 明确 N10 应测的业务、平台和组织指标；
- 能从一个具体场景完整说明价值如何发生；
- 长期价值落在 **Enterprise AI Business Capabilities**，而不是“多做几个 Agent”。
